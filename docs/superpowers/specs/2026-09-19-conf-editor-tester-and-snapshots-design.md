# Whole-tree MailScanner configuration editor, tester and snapshots

*2026-09-19 — design for editing every file under the MailScanner conf dir from
the Config tab, validating and backing up each save, testing a configuration
before it goes live, and exporting/importing the configuration as one archive.*

## Problem

The Config tab edits exactly two files, `MailScanner.conf` and MSFE-NG's own
`config.toml`, through a hard-coded allowlist. Everything else an administrator
tunes lives next to them and is unreachable from the UI: `spamassassin.conf`,
`spam.lists.conf`, `virus.scanners.conf`, the filename/filetype/archives rules,
the phishing custom lists, `conf.d/` fragments, `mcp/`, the rulesets under
`rules/` that sync does not generate, and the notification templates under
`reports/`. A save keeps one `.msfe-ng.bak` of the original file forever, never
validates, never reloads, and cannot be undone once the second save happens.
`msfe-ng backup` archives `/etc/msfe-ng` only, so neither a full restore nor a
move to another server is possible without an ssh session.

## Design

Four cooperating pieces in `msfe-core`, one API namespace, one CLI noun, and a
two-pane Config tab.

### Catalog — `confcatalog`

The catalog is the only way a request may name a file. `scan()` walks the two
roots — the engine's etc dir from `layout::resolve` and the directory of
`config.toml` — one level into `conf.d/`, `mcp/`, `rules/`, `custom/` and
`reports/` (the `reports` symlink is followed once and its target recorded),
and classifies every entry by a pure function of its relative path:

| Path | Kind | Reload | Validator |
|---|---|---|---|
| `MailScanner.conf` | key/value (plain) | restart | MailScanner lint on the stage |
| `conf.d/*.conf` | key/value (plain) | restart | MailScanner lint after apply (see below) |
| `spamassassin.conf`, `mcp/mcp.spamassassin.conf` | plain text | restart | `spamassassin --lint -p` on the stage |
| `mcp/*.cf` | plain text | restart | syntax only |
| `filename|filetype|archives.*.rules.conf` | filename-rules table | reload | MailScanner lint on the stage |
| `spam.lists.conf` | spam-lists table | restart | MailScanner lint on the stage |
| `virus.scanners.conf` | virus-scanners table | restart | MailScanner lint on the stage |
| `phishing.*.custom` | host list | reload | syntax only |
| `phishing.*.conf`, `*.master`, `*.backup` | read-only (generated by ms-update-phishing) | — | — |
| `country.domains.conf` | plain text | reload | syntax only |
| `rules/<sync-managed>.rules` | read-only (generated by sync; Rules tab) | — | — |
| `rules/*.rules` (other) | rule table | reload | MailScanner lint on the stage |
| `reports/**/*.txt` | plain text | none | UTF-8 |
| `custom/*.pm`, `defaults`, `*.rpmnew`, `*.rpmsave` | read-only | — | — |
| `msfe:config.toml` | key/value (toml) | none | `Config::from_toml_str` |

Ids are `ms:<rel>` / `msfe:<rel>`; `resolve(id)` answers only ids the scan
produced, so no request can reach outside the two trees. `creatable()` allows
new `conf.d/*.conf` and `rules/*.rules` files whose names pass
`service::safe_name`.

The policy files under `/etc/msfe-ng` are owned by the Settings, Lists and
Rules tabs; they are not listed in the editor but are part of a snapshot.

### Grammars — `msgrammar`

Line-oriented, comment-preserving parsers in the style of `rulefile`: every
line is `Blank | Comment | Row | Unparsed`, rows re-serialize to MailScanner's
canonical TAB form, and a file round-trips byte-for-byte when nothing changed.

- Filename/filetype rules: `action TAB pattern TAB log text TAB user text`
  where the action is `allow`, `deny`, `deny+delete`, `rename` or `rename to
  .ext`; MailScanner splits on tabs, so a line with fewer than four tab fields
  is re-split on two-or-more spaces and flagged as normalized. Patterns are
  compile-checked by one run of the engine's perl (`eval { qr/$_/ }`), the
  class of error `--lint` never reports because these files are compiled at
  scan time.
- `spam.lists.conf`: `NAME  zone` (rows from `engine::parse_rbl_definitions`).
- `virus.scanners.conf`: `name  wrapper  dir`.
- Phishing custom lists: one hostname per line.

`spamassassin.conf` is deliberately *not* a key/value grid: `score`, `header`,
`body`, `meta` and `describe` repeat, so a grid would be wrong rather than
merely untyped. It gets the raw editor and SpamAssassin's own lint.

### Schema — `msdefs`

The engine's `MailScanner/ConfigDefs.pl` (found through the perl `-I` paths as
`layout::supports_exim_command` already does) is the only description of the
directives MailScanner knows. Its `[Translation,Translation]` section maps
internal names to external ones; the `[Simple|First|All, YesNo|Number|File|
Command|Dir|Other]` sections list `internal default [yes/no words…]`. A conf
key maps to its definition by lowercasing and dropping every non-alphanumeric
character (`Archives: Filename Rules` → `archivesfilenamerules`), translated
back to the internal name when the translation table has it. `First` and `All`
directives accept a ruleset. Descriptions come from the comment block above
each entry in `MailScanner.conf` itself. Without a readable `ConfigDefs.pl` the
editor degrades to today's untyped grid.

### The save pipeline — `confsave`

Every write — save, restore, import — goes through one function:

1. `expect_mtime` differs from the file's → `stale` (409); the UI reloads.
2. Unchanged text → nothing happens (no backup, no reload).
3. Syntax validation by kind (the grammar parsers, `rulefile`, `Config`).
4. **Stage**: `cp -a` of the etc dir into `backup_dir/.stage/<pid>-<n>/etc`,
   the edit applied there, and the staged `MailScanner.conf` rewritten so every
   `%variable%` and every directive whose expanded value starts with the live
   etc dir points into the stage instead (`%etc-dir%`, an absolute
   `%rules-dir%`, `%report-dir%` when it is under etc, absolute `Filename
   Rules = /etc/MailScanner/…`). The validator runs there: `MailScanner --lint
   <staged conf>` or `spamassassin --lint -p <staged prefs>`. Verified on
   MailScanner 5.5.3: the positional conf path is honoured (`Reading
   configuration file <staged path>`); `conf.d/` however is always read from
   the live directory, so `conf.d` fragments are the one kind validated after
   apply. Lint failure → the live file is untouched; the report carries the
   parsed findings and the transcript.
5. **Promote**: copy the live file to `backup_dir/conf/<root>/<rel>/<stamp>`
   with a `<stamp>.meta` (`reason=save|restore|import`), keep the newest 50,
   then `sync::atomic_write` (mode and owner preserved).
6. After-apply lint only for `conf.d` (and as the fallback when the engine did
   not name the staged conf in its transcript): failure writes the backup back
   and reports `rolled_back`.
7. Reload according to the kind: `restart` through `service::control` when the
   service is active (MailScanner reads these files at start only), `reload`
   through `sync::reload_mailscanner` (rulesets are re-read per batch), or
   nothing. A failed restart is reported, not rolled back — the file passed
   lint; the problem is the service. A lint timeout (180 s cap) is
   inconclusive: the file is kept and the report says so.

Saves are synchronous under the daemon's write lock: rollback must be atomic,
a typical lint takes 5–20 s and the cPanel CGI allows 300 s. The UI shows
progress and offers "save without lint". Background jobs remain the fallback
if field experience shows WHM timeouts.

The existing `/api/service/conf*` routes keep their paths and answer shapes
and simply run through this pipeline.

### The tester — `conftest` and `confcheck`

`conftest::run(edits, parts)` produces a `TestReport`: a sorted list of
findings `{level ok|warn|fail, source mailscanner|spamassassin|msfe, file,
key, line, message}` plus the raw transcripts. With `edits` it uses the same
`Stage` as a save, without promoting — "test my unsaved changes" and "save"
are one code path.

Findings come from three sources:

- **MailScanner --lint**, parsed line by line (unknown lines stay in the
  transcript): `Error in line N of <path>`, `Cannot open ruleset file …`,
  `Value of <key> cannot be …`, `Cannot …`/`Could not …` → fail;
  `Warning …` → warn; `MailScanner.conf says "Virus Scanners = X"` matched
  against `Found these virus scanners installed:`; `Read N hostnames from the
  phishing …` (0 → warn); `SpamAssassin reported no errors.` → ok. Staged
  paths map back to catalog ids; a quoted directive name maps to `key`.
- **spamassassin --lint -p <prefs>**: `config: failed to parse line …` →
  fail with the file, other `config:` lines → warn, `plugin:`/`warning:` →
  warn, non-zero exit → fail. (Today's SpamAssassin lint button never read
  MailScanner's `spamassassin.conf` at all; `-p` fixes that.)
- **confcheck** — cross-file consistency on the live or staged tree: every
  File/Dir/Command directive exists (or names an existing ruleset); every
  referenced ruleset parses and its values fit the directive's type; `Virus
  Scanners` entries exist in `virus.scanners.conf` with executable wrappers;
  `Spam List` names are defined and not defunct; filename rules parse and
  their patterns compile; phishing custom lists and `conf.d` fragments parse;
  directives unknown to the schema (typos); files readable by the run-as user
  and work/quarantine/lock dirs writable by it. The doctor checks that already
  cover part of this (conf found, Exim wiring, rules dir, SpamAssassin module,
  clamd socket, envelope-sender header, DNS blocklists, phishing updates) are
  called once and mapped, never duplicated.

**Test message.** Driving `MailScanner --debug` against a hand-built Exim
spool is not shipped: spool `-H`/`-D` pairs are Exim-version specific,
`--debug` still delivers through the real MTA and touches quarantine and lock
state, and the verdict lines are unstructured. Instead the Config tab offers a
clearly labelled *simulation* — `spamassassin -t -p <prefs>` as the run-as
user (with `-L` for an offline run), `clamdscan` (cPanel ships it under
`/usr/local/cpanel/3rdparty/bin`), the attachments matched against the
filename/filetype rules, and the MailScanner actions *predicted* by resolving
the sample's addresses through the rulesets with first-match semantics — as
the background job `conf-test-message` (samples: clean, GTUBE, EICAR as an
attachment named `eicar.com`, or an uploaded `.eml` up to 3.9 MB base64), and
next to it the authoritative end-to-end test: `msfe-ng selftest` as the job
`selftest`, whose real verdicts the UI reads back from the mail log.

### Snapshots — `snapshot`

`export` stages `manifest.json` (format, time, host, MSFE-NG and MailScanner
versions, both root paths, every file with size, mode and sha256 from
`sha256sum` when present), `mailscanner/<rel>` for every catalog entry except
the generated phishing lists, and `msfe/` for the whole `/etc/msfe-ng`, then
`tar czf`. Snapshots land in `backup_dir/snapshots/` as
`msfe-ng-snapshot-<host>-<stamp>.tar.gz`, mode 0600 (`config.toml` holds the
database password).

`inspect` lists the archive first and refuses any entry that is not
`manifest.json`, `mailscanner/…` or `msfe/…`, contains `..`, or is absolute —
before extracting into `backup_dir/snapshots/.incoming/<token>/`. Each file is
compared with the live catalog: same, changed, new, read-only live, or not in
the catalog. An archive without a manifest whose entries start with
`msfe-ng/` is the legacy `msfe-ng backup` format and is treated as the `msfe`
root, so old tarballs still restore.

`import` writes the selected ids through `confsave` with one lint and one
restart for the whole set; `msfe` policy files go through `atomic_write`,
`sync::run` and a reload as the Rules tab does. New files take the manifest's
mode, root ownership, then the live directory's owner when that is not root.

Binary archives cannot cross the daemon's `String` request/response bodies
(4 MiB cap) or the panel CGI, so the API carries them as base64 inside JSON;
the browser decodes to a `Blob` for download and reads uploads with
`FileReader`. Uploads above ~3.9 MB are refused with a clear message.

### API

All new routes sit under `/api/conf/*`, `/api/snapshot/*` and the existing
`/api/jobs/<name>`; the flat method+path match and query-string convention of
`api.rs` are kept.

| Route | Purpose |
|---|---|
| `GET /api/conf/tree` | roots, files with kind/reload/editability, `pending_restart` |
| `GET /api/conf/file?id=` | content, parsed view, schema, history count |
| `PUT /api/conf/file` | `{id, content|changes|rows, lint, reload, expect_mtime}` → save report |
| `POST /api/conf/create` | new `conf.d`/`rules` file |
| `GET /api/conf/history?id=`, `GET /api/conf/history/view?id=&stamp=`, `POST /api/conf/restore` | backups |
| `POST /api/conf/test`, `GET /api/conf/test/last`, `GET /api/conf/test/message/last` | tester |
| `POST /api/snapshot/export`, `GET /api/snapshot/list`, `POST /api/snapshot/inspect`, `GET /api/snapshot/diff?token=&id=`, `POST /api/snapshot/import` | snapshots |
| `POST|GET /api/jobs/conf-test-message`, `/api/jobs/selftest` | test-message jobs |

### CLI

`msfe-ng snapshot export [file] [--only mailscanner|msfe]`, `snapshot import
<file> [--dry-run] [--only …] [--yes]`, `snapshot list`; `backup` and
`restore` become aliases over the same code. `msfe-ng conf test [--no-lint]
[--json] [--with <id>=<file>]…` and `conf test-message <clean|gtube|eicar|
path.eml> [--offline] [--json]`. All go through the existing per-command flag
allowlist; a test with any failing finding exits 1.

### UI

The Config tab becomes a file tree (grouped by root and directory, kind badge,
lock with reason, filter, "new file") beside an editor with a toolbar: path,
reload badge, Form ⇄ Raw, Save, Discard, History, Test; the tab's top bar
carries Test configuration, Export snapshot and Import snapshot. Editors:
key/value grid with typed inputs and descriptions, a ruleset picker for
ruleset-capable directives, table editors for rules, filename rules, spam
lists, virus scanners and host lists, and a raw textarea with a line diff
before save. Save results render the validation findings and the restart
transcript inline. The existing maintenance cards stay below. Below 720 px
the tree becomes a select.

## Risks

- `ConfigDefs.pl` unreadable → untyped grid, as today.
- Lint blocks the write lock for up to 180 s → progress UI, "save without
  lint", timeout treated as inconclusive.
- Restarts interrupt scanning for seconds → "apply without reload" plus a
  `pending_restart` banner and doctor check; imports restart once.
- `reports/` is a package-owned symlink target → written through the symlink,
  recorded in the manifest, upgrade warning in the docs.
- The sync cron regenerates managed rules and `apply_archive` rewrites
  `Archive Mail` → managed rules are read-only; `expect_mtime` catches races.
- A `config.toml` from another host inside a snapshot → unchecked by default
  in the import wizard.
- MCP rules are a separate SpamAssassin instance → syntax check only for now.
