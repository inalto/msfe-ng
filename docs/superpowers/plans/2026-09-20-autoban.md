# Auto-ban and match rules — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Temporary csf bans driven by MailScanner verdicts (per-severity thresholds) and admin-defined match rules (subject/sender/header/body) that block delivery and ban the source, configurable from the Settings tab and from a message row.

**Architecture:** A pure decision engine (`autoban::evaluate`) over `maillog` rows fed by a minute cron (`msfe-ng autoban run`) that bans through `csf -td` and records every ban in a new `autoban` table; match rules stored as JSON in the policy dir and rendered by `sync` into `/etc/mail/spamassassin/msfe-ng-match.cf` (score 100 = never delivered via the high-spam action, 0.01 = tagged for banning only), validated with the engine's own perl `qr//` and `spamassassin --lint`.

**Tech Stack:** Rust (msfe-core / msfe-ngd / msfe-cli, no new crates), MySQL migration, vanilla JS in `web/whm/index.html`, csf, SpamAssassin.

**Spec:** `docs/superpowers/specs/2026-09-20-autoban-design.md`

## Global Constraints

- No new crate dependencies (the workspace has none beyond `msfe-api`); JSON via `crate::json::Json`.
- Every subcommand's flags are declared in the CLI flag table (`crates/msfe-cli/src/main.rs` `flags_for`), tests in `crates/msfe-cli/tests/cli.rs` reject unknown flags.
- `cargo fmt`, `cargo clippy --all-targets` warning-free, `cargo test` green before each commit; CI runs the same plus shellcheck.
- Defaults ship disabled: `autoban_high_enabled=false`, `autoban_spam_enabled=false`, no match rules.
- Safeguards fixed (never own/loopback/private, never `csf.allow`/already denied, never an IP with clean mail in the window, no double bans).

### Task 3: The decision engine (pure)

**Files:** `autoban.rs`.

**Produces:**
```rust
#[derive(Debug, Clone, PartialEq, Eq)] pub struct Row { pub id: u64, pub ts: u64, pub ip: String, pub isspam: bool, pub ishighspam: bool, pub matched: Vec<u32> /* rule ids named in spamreport */ }
pub fn matched_rules(spamreport: &str) -> Vec<u32>;                        // "MSFE_MATCH_3 100.00" → [3]
#[derive(Debug, Clone, PartialEq, Eq)] pub struct Candidate { pub ip: String, pub reason: String /* high|spam|match */, pub rule_id: Option<u32>, pub count: u32, pub seconds: u64, pub sample_id: u64, pub detail: String }
pub fn evaluate(rows: &[Row], rules: &Rules, matches: &[MatchRule], now: u64) -> Vec<Candidate>;
```
Rules: rows older than the widest window are ignored; per IP: high count in `high.window` ≥ `high.count` → candidate high; spam count (isspam, not high) in `spam.window` ≥ count → spam; any row naming an enabled match rule with `ban_secs>0` → match (immediate). Clean-mail exemption: an IP with a row that is neither spam nor high in the candidate's window is skipped. One candidate per IP: the longest `seconds` wins; `detail` like `MSFE-NG auto-ban: 3 spam messages in 1h` / `MSFE-NG auto-ban: matched rule #3 (comment)`. Output sorted by ip.

- [ ] Tests: `threshold_reached_only_inside_the_window`, `high_count_one_bans_on_first_message`, `clean_mail_in_the_window_exempts_the_ip`, `match_rule_bans_immediately_with_its_duration`, `longest_ban_wins_per_ip`, `disabled_rules_never_fire`, `matched_rules_parses_the_report`.
- [ ] Implement; test; commit "Auto-ban: the decision engine".

### Task 6: CLI, cron, API

**Files:** `crates/msfe-cli/src/main.rs` (`autoban <status|run [--dry-run]|rules>`, flag table `("autoban", Some("run")) => Some(DRY)`, usage/help lines), `packaging/cron/msfe-ng` (`* * * * * root /opt/msfe-ng/bin/msfe-ng autoban run >/dev/null 2>&1`), `crates/msfe-ngd/src/api.rs`:

- `PUT /api/autoban/rules` `{rules:[…]}` → validates each (`check_regex` under `layout::resolve(cfg).perl`, field/matcher/ban_secs sanity), assigns ids to new rules (`id:0`), saves, `sync::run` → `{ok, changed, lint}` or 400 `{error}` with nothing written.

- `GET /api/autoban/history?limit=50` → rows.
Thresholds are saved by the existing `POST /api/service/conf/apply {which:'msfe', changes}`.
